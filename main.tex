\begin{frame}{Memory}
    Holds both instructions and data.

    \begin{itemize}
      \item \textbf{Unified:} Both instructions and data are stored in the memory under the same address system
      \item \textbf{Random-access:} any address can be reached in roughly the same time
      \item \textbf{Volatile:} turning the power off wipes the contents
    \end{itemize}

\section{Specialized Hardware}

\begin{frame}{Shape of AI compute}
\begin{itemize}
  \item Modern powerful AI models are mostly based on neural networks, whose compute involves lots of \textit{matrix multiplication}
  \item Matrix multiplication can be decomposed into lots of \textit{independent} weighted sums, each very elementary to compute
\end{itemize}
  AI compute prioritizes \textbf{parallelism} over \textbf{complexity}.

% TODO: Embed online images showing how matrix multiplication can be decomposed into elementary calculations
\end{frame}

\begin{frame}{Limitation of generic computers}
  CPUs specialize in \textbf{sequential} execution of \textbf{complex instructions}.

\begin{itemize}
  \item Each CPU core can handle complex instructions relatively fast, but there are usually \textit{only a few cores} in a CPU
  \item CPUs are usually paired with memory with \textit{low latency} but also relatively \textit{low bandwidth}
\end{itemize}

  \note{
    Letting CPUs handle AI compute is like letting one mathematics professor handle a thousand elementary school math problems.
  }
\end{frame}

\begin{frame}{Limitation of generic computers}{Latency vs. bandwidth}
\begin{itemize}
    \item \textbf{Latency}: How long a single piece of data takes to arrive once requested
    \item \textbf{Bandwidth}: How much data can be moved per second
\end{itemize}
Unfortunately, these are two opposing properties of a memory system.
\end{frame}

\begin{frame}{Ideal hardware for AI compute}
  Hardware capable of performing elementary computations in parallel.

\begin{itemize}
  \item Have \textit{a lot of cores}, each of which can be simple and only capable of executing elementary instructions
  \item Pair with memory with \textit{high bandwidth} at the expense of relatively \textit{high latency}
\end{itemize}

  \note{
    Letting a thousand elementary school students solve a thousand simple math problems.
  }
\end{frame}


\begin{frame}{Common specialized hardware}{Graphics Processing Unit (GPU)}
\begin{itemize}
  \item Originally designed for rendering computer graphics (such as video games and GUIs)
  \item Rendering computer graphics and computing AI models are very similar in shape
\end{itemize}

\begin{itemize}

\begin{frame}{Common specialized memory systems}
\begin{itemize}
  \item \textbf{DDR (baseline):} commonly paired with CPUs, 50--100 GB/s bandwidth
  \item \textbf{GDDR:} commonly paired with gaming GPUs, $\sim$1.8 TB/s bandwidth
  \item \textbf{HBM:} usually only seen on high-end data center GPUs, >2.0 TB/s bandwidth
\end{itemize}

\begin{block}{Fun fact}
  Technically it is possible to:
\begin{itemize}
  \item Pair CPUs with GDDR for a general computer
  \item Pair GPUs with DDR for rendering graphics or computing AI models
\end{itemize}
\end{block}
\end{frame}


\begin{frame}{Coming back to Von Neumann}
    Specialized hardware is what makes most modern AI systems practical, but it has not replaced the Von Neumann architecture.

\vspace{0.5em}
    Look at any modern computer, even a real AI computer in a data center.
    \begin{itemize}
        \item A CPU sits at the center
        \item GPUs, TPUs, or NPUs attach as accelerators through the bus
        \item All share access to memory, coordinated by the OS on the CPU
    \end{itemize}

    \vspace{0.5em}
    The CPU is still the executive chef.
    The accelerators are highly skilled sous chefs hired for one specialty.
\note{
}
\end{frame}



\section{Exercise}

\begin{frame}{Run a model on different hardware}
    The point of the exercise is to feel the difference between CPU and GPU on the same model.
    Use Google Colab or AI-LAB, and reuse the image classification setup from Module A.4.

    \begin{block}{Outline}
        \begin{enumerate}
            \item Move the model and a batch onto whichever device the runtime exposes via \texttt{.to(device)}, where device is \texttt{"cuda"} or \texttt{"cpu"}
            \item Switch the runtime between CPU and GPU. Restart and rerun after each switch
            \item Time how long one image takes on each device. Average over a few runs, since the first run has warm-up overhead
        \end{enumerate}
    \end{block}
\note{
}
\end{frame}


\begin{frame}{Extensions}
    \begin{enumerate}
        \item Print the parameter count and estimate the model's memory footprint at 4 bytes per parameter
        \item Switch to a heavier model like ResNet-152 or a HuggingFace ViT and repeat the timing. The CPU-GPU gap should grow
        \item Run a small batch of images at once. GPU performance scales with batch size much better than CPU performance does
    \end{enumerate}

    \vspace{0.5em}
    By the end you should have a hands-on feel for why specialized hardware matters, and a number you can point to next time someone tries to sell you an AI computer.
\note{
}
\end{frame}


\begin{frame}{What you should walk away with}
    By the end of the exercise, you should be able to:
    \begin{enumerate}
        \item Be familiar with the Von Neumann architecture
        \item Understand the pros and cons of generic computing hardware and specialized AI computing hardware
    \end{enumerate}

    \vspace{0.5em}

\end{frame}
